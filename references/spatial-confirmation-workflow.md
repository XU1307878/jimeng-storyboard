# 多人场景空间确认工作流

当场景中有两人以上、固定座位、正反打、进出门、跨镜移动，或用户提供了带人物的场景参考图时，先确认空间，再写正式提示词。资产由用户制作；本工作流只输出纯文本空间草图和提示词约束。

## 1. 先问是否锁定

如果用户没有明确说明，先问一句：

> 本场是否严格锁定参考图中的人物站位和空间关系？也可以由我先画纯文本俯视图，你确认后再锁定。

三种状态：

- `参考图锁定`：参考图中的座位、朝向、距离、前后层级和固定家具关系为事实。导演不得另写一套冲突站位。
- `文字俯视图锁定`：先根据剧本和场景图提出纯文本俯视图，必须经用户确认后才能成为正式空间事实。
- `不锁定`：参考图只控制人物或场景设计；导演可以重新设计站位，但须标为导演方案。

未收到确认时，状态写成 `待确认`。不得把草案位置、左右关系或轴线写进可直接生成的最终提示词。

## 2. 先读景深顺序

画俯视图前，先把参考图转换成一条从背景到摄影机的景深链：

> 后墙/窗/门 → 固定家具 → 后排人物 → 前排人物 → 摄影机

每个物体只能出现在这条链的一个层级。若参考图显示座椅在所有人物身后，就不得在俯视图中把座椅画到人物之间。

## 3. 纯文本俯视图格式

纯文本俯视图必须包含：

- 场景边界；
- 后墙、门窗、桌椅等可验证固定地标；
- 人物圆点与姓名；
- 人物面向箭头；
- 必要的移动路线；
- 摄影机可活动区域；
- 状态：`待确认`或`已确认`。

示例：

```text
【纯文本俯视图｜场次名｜状态=待确认】

                         后墙
┌──────────────────────────────────┐
│  门       固定背景/屏幕       门  │
│                                  │
│  ┌────────────────────────────┐  │
│  │          固定座椅           │  │
│  └────────────────────────────┘  │
│                                  │
│       ●人物A       ●人物B         │
│            \       /              │
│             ●人物C                │
│                                  │
│          摄影机可活动区域          │
└──────────────────────────────────┘
                         前方
```

图下追加一条景深链和一句物理校验：

> 景深链：后墙 → 固定座椅 → 人物A/人物B → 人物C → 摄影机。固定座椅不在人物之间。

## 4. 动态场次分状态

人物起身、离席、换位、入场或退场时，不把所有位置叠在一张图里。分别画 `状态A（动作前）`、`状态B（动作后）`；移动使用 `●──→`，并写明终点。

## 5. 正式提示词写法

用户确认后，正式提示词只保留一次空间锁定声明：

> 人物站位、朝向、距离、邻接关系及固定家具位置严格继承已确认的纯文本俯视图；不交换座位，不改变前后层级。摄影机只在已确认的活动区域内取景。

后续内部镜头只写动作、表演、视线目标、景别和运镜，不重复发明左/右座位。需要改变位置时，先更新状态图并再次确认。

## 6. 冲突检查

交付前逐项检查：

1. 俯视图的背景到摄影机顺序是否与参考图一致；
2. 桌椅是否错误插入人物之间；
3. 人物数量、姓名、座位和面向是否与确认版本一致；
4. 镜头是否越出摄影机活动区域或无说明越轴；
5. 横屏/竖屏是否只改变裁切，而没有移动人物；
6. 是否出现未经确认的新出口、楼梯、空座、人物或道具；
7. 说话者是否可见且只有说话者口型运动。

任何一项无法由参考图、剧本或用户确认支持，都标为待确认，不写成事实。
