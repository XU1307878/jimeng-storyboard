## 1. 原则

视频模型会在未锁定的变量上替导演做决定。先确认人物、场景、道具、位置、轴线和动作结果，再写运镜与提示词。

把信息分成三类：

- **事实**：剧本或用户已明确说明，不得改动。
- **决策**：导演需要选择的机位、轴线、走位、焦点和节奏。
- **假设**：资料不足时的临时补全，必须标为“草案/待确认”，不能伪装成事实。

## 2. 场次事实表

先为每个场次建立一行事实表：

| 字段 | 内容 |
|---|---|
| 场次ID | SC01、SC02……，全项目唯一 |
| 时间与时长 | 剧情时段、计划秒数 |
| 世界模式 | D日常 / S山海 / T镜内切换 |
| 地点 | 主空间、相邻空间、入口和出口 |
| 出场人物 | 本场实际出现的人物 |
| 关键道具 | 被拿取、交付、观察或推动剧情的物件 |
| 对白 | 精确台词，不混入视觉提示词 |
| 动作节拍 | 按发生顺序列出可见动作 |
| 情绪转折 | 触发点、变化、落点 |
| 揭示信息 | 观众在本场新知道什么 |
| 连续性事实 | 服装、伤痕、天气、手中物、前场遗留状态 |

事实表只提取，不先设计镜头。

## 3. Gate A：资产锁定

### 资产状态

给每个生产资产分配稳定ID和状态：

- **已提供**：存在可用文件，记录路径与@编号。
- **需要生成**：在写正式分镜前先生成角色、场景或道具资产。
- **文本锚定**：不需要图片，文字规格足以稳定生成。
- **冲突待确认**：参考图、剧本和用户指令互相矛盾。
- **不适用**：本场不需要。

### 资产请求表

| 资产ID | 类型 | 名称 | 状态 | 用途 | 缺失信息 | 建议比例 |
|---|---|---|---|---|---|---|
| CHR-001 | 人物 | 姜禾 | 已提供 | 身份与服装设计 | 无 | 16:9角色锁定图 |
| ENV-D05 | 场景 | 废弃车站 | 需要生成 | 空间结构与材质 | 出入口位置 | 16:9场景图 |
| PROP-003 | 道具 | 夜单手机界面 | 文本锚定 | 卡片层级与色彩 | 无 | 后期UI |

### 门禁规则

- 缺少主角身份、核心场景结构或剧情关键道具时，先交付资产请求，不直接声称“生产已锁定”。
- 用户允许先做草案时，可以继续，但在制作摘要、场次事实表和空间锁定中写明假设。
- 参考图的主角色必须固定。不得把设计参考自动升级为首帧、锁脸或目标画风。
- 项目级@编号保持稳定；单镜头只选用本镜需要的子集。

## 4. Gate B：空间锁定

以下情况必须建立空间锁定：两人以上对白、追逐、进出门、跨镜头拿取道具、正反打、重复回到同一地点、左右运动具有叙事意义。

### 空间图必须包含

- 场次ID和版本。
- 画面顶部对应的真实方向或固定地标。
- 区域边界：站台、铁轨、房间、走廊、门窗、桌椅等。
- 人物初始位置、朝向和目线目标。
- 关键道具位置和接触人。
- 主动作路径。
- 主轴线ID，例如 AX-A。
- 允许的银幕方向，例如姜禾左→右、鹿九右→左。
- 计划机位与视线目标。
- 状态：草案或已确认。

### 文本锁定格式

~~~text
空间锁定：SC01 / AX-A / 状态=已确认；
人物=姜禾L1面向右，鹿九R3面向左；
目线=姜禾→鹿九；
道具=手机在姜禾右手；
运动=姜禾左→右；
地标=铁轨横贯后景，出口位于画面左后方。
~~~

### 轴线规则

- 正反打保持在同一轴线一侧。
- 运动方向跨镜头保持一致。
- 必须越轴时，使用能看见越轴过程的移动镜头、正面中性镜头或重新建立空间的大远景，并声明新轴线。
- 近景继承上一个建立镜头的左右位置和目线。
- 场景参考图只锁空间关系，不锁死原图机位。

需要图形化确认时，先写空间JSON，再运行：

~~~powershell
python scripts/render_spatial_map.py scene-lock.json --output scene-lock.svg
~~~

## 5. Gate C：镜头设计

每条镜头卡必须回答：

1. 观众这一镜首先看谁或看什么？
2. 这一镜唯一的叙事任务是什么？
3. 主体发生哪一个主要动作？
4. 情绪通过哪些可见信号发生变化？
5. 摄影机为何移动或为何保持不动？
6. 结尾留下什么可继承状态？
7. 最可能生成错什么？

镜头拆分触发条件：

- 说话人变化。
- 动作目的变化。
- 视觉焦点变化。
- 情绪转折。
- 信息揭示。
- 世界风格变化。
- 当前动作无法在15秒内清楚完成。

## 6. 微表演编码

不要只写情绪名称。使用二至四个可观察信号：

- **目线**：看向谁、停留多久、何时躲开、何时回看。
- **眼睑/眉间**：眨眼频率、眼睑收紧、眉间轻压。
- **嘴与下颌**：笑意停住、嘴角回落、下颌绷紧、吞咽。
- **呼吸**：短吸气、屏息、缓慢吐气、胸口起伏。
- **手部压力**：指尖收紧、抓握松开、接触面和物体反馈。
- **肩颈与姿态**：肩膀微收、颈部后撤、背部挺直或塌下。
- **重心**：从前脚移到后脚、身体停住、准备转身。
- **皮肤反应**：眼眶微红、雨水和汗水变化；只在景别看得见时使用。

格式：

~~~text
微表演：主体=姜禾笑意停住，短吸气后视线从外婆移到蛋糕盒，右手指尖压紧盒盖，重心退到后脚；背景=外婆保持不动，只轻微抬眼。
~~~

背景人物只写克制反应，不与主体争夺焦点。

## 7. 当前镜头最小引用

先保留项目级完整资产表，再为每镜选择最小集合：

- 只有在画面可见且确实控制身份、场景、道具、动作或声音时才引用。
- 同一作用不要堆多个近似参考。
- 素材映射中的每个@编号必须出现在该镜视觉提示词中。
- 视觉提示词中的每个@编号必须先在该镜素材映射中声明。
- 一镜超过4个参考时优先拆镜或删除弱参考；确有必要时说明原因。
- 不因资产存在就机械地在每镜引用它。

## 8. 模型错误预判

每镜列出一至三个高概率错误，并给出正向预防：

~~~text
模型风险：风险=鹿九抢夺前景焦点、姜禾目线反转；预防=焦点持续锁定姜禾面部，鹿九保持右后景虚焦，姜禾始终向画面右侧看。
~~~

优先写物理和空间事实，再补简短禁止项：

- 身份漂移 → 固定可见脸部、发型和服装锚点。
- 目线错误 → 写清视线目标和银幕方向。
- 人物瞬移 → 写清起点、路径、终点。
- 道具漂移 → 写清哪只手、接触面、重量和结尾位置。
- 手部错误 → 降低同时动作数量，写明抓握结构。
- 风格串场 → 只使用当前世界前缀，D与S分开生成。
- 背景抢戏 → 锁定焦点、景深和背景反应幅度。
- 运镜冲突 → 只保留一个主运镜。
- 乱码 → 生成空白信息区，精确文字后期添加。

## 9. 修订与唯一版本

- 聊天内容是讨论记录，不是最终生产文件。
- 每次确认修改后，更新Markdown源文件并重新生成HTML。
- HTML页头记录项目名、版本、生成时间和状态。
- 最终交付只认最新HTML与其对应Markdown源文件。
- 旧版本可归档，但不要同时标记为“最终版”。
